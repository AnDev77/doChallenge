# 이메일 인증과 가입 요청의 일회용 연결

기준일: 2026-10-29. 최신 중간 평가와 사용자의 이메일 인증 요구를 반영한 오늘의 핵심 작업이다. 금융 채팅을 제거한 것이 아니라 회원 신뢰 경계를 먼저 보강한다.

## 시작

기존 코드에는 SMTP 발송, Redis 코드 보관, 인증 확인, 가입 API가 이미 있다. 그러나 확인 뒤 이메일별 `true`만 저장하고 가입 요청은 이메일만 확인했다. 인증을 수행한 클라이언트가 보유해야 할 가입 증표가 없었다. Java main `8dd842c`에서 독립 브랜치를 만들었으며 기존 채팅 인증 PR #6은 덮어쓰지 않았다.

## 구현

- 확인 성공 때 SecureRandom 32바이트의 가입 전용 증표를 발급한다. 브라우저에는 증표, Redis에는 SHA-256 해시만 전달·저장한다. 증표는 로그인 JWT가 아니며 이메일 하나의 가입에만 사용한다.
- 확인 응답 `data.verificationToken`, `data.expiresInSeconds=600`. 가입 요청에는 기존 이메일·비밀번호·닉네임과 `verificationToken`이 필요하다. 이전 클라이언트의 증표 없는 가입은 더 이상 허용하지 않는다.
- Redis Lua로 코드 확인→코드 소진→10분 증표 저장을 묶고, 가입 증표 비교→삭제도 원자적으로 처리한다. 새 키 공간은 이전 이메일별 인증 플래그를 신뢰하지 않는다. 동일 이메일 키는 같은 Redis Cluster 슬롯에 배치하지만 실제 Cluster는 시험하지 않았다.
- 가입 증표를 소진한 후 회원 DB 저장을 호출한다. Redis와 DB의 분산 트랜잭션을 가장하지 않는다. DB 저장 실패 또는 응답 유실 시 증표를 자동 복원하지 않으며 사용자는 재인증하거나 기존 가입 여부를 확인해야 한다. 이 가용성 제약을 UI 안내에 반영해야 한다.

## 시험과 오류 기록

- 단위 시험: 무작위 증표/해시 저장 경계, 틀린·없는 코드 거부, 누락·변형·소진 증표 거부, SMTP 실패 시 미인증, 증표 실패 시 회원 저장 미호출, DB 실패 시 처리 순서.
- 실제 Redis 시험 6개: 코드와 증표의 일회성, 다른 이메일/이전 인증 플래그 거부, 코드 만료, 10분 증표 TTL과 만료, 동시 가입의 단일 성공, 동시 확인의 단일 증표.
- 로컬 `bash ./gradlew test bootJar --no-daemon`은 Gradle 배포본 다운로드 단계의 `Network is unreachable`로 실패했다. 로컬 JDK도 17이라 Java 21 시험을 실행했다고 주장하지 않는다.
- 원격 CI에 Java 21·Redis 7.4를 구성하고 전체 시험·bootJar·Redis 시험 생략 여부·가입 응답 클래스의 JAR 포함을 확인한다. 실제 결과는 해당 PR의 게이트에 기록한다.

## 공개 회원 서비스 배포 전 남은 필수 조건

- 이메일/IP별 재발송 대기·시도 횟수 제한, 코드 대입 방어와 SMTP timeout/오류 응답을 구현·시험한다. 이번 변경만으로 공개 가입 준비 완료가 아니다.
- 실제 SMTP 발신 계정/도메인·TLS 설정과 사용자 지정 시험 수신처가 필요하다. 비밀값은 배포 비밀 저장소로 관리한다. 실제 발송/수신 성공은 아직 확인하지 않았다.
- 웹의 발송→코드 입력→확인→증표 포함 가입→로그인 연결과 만료·재전송·DB 실패 안내를 구현한다. 증표를 URL이나 영구 저장소에 남기지 않는다.
- 배포 서버 DB·Redis 및 두 브라우저 시험, 기존 회원·이메일 정규화 정책을 확인한다. 이번 PR은 금융 종목방, 실제 채팅, 운영 메일 검증 완료를 의미하지 않는다.

## 근거와 독립 평가

Redis의 Lua 원자성: https://redis.io/docs/latest/develop/programmability/eval-intro/
OWASP의 난수·만료·일회용 증표 원칙(비밀번호 복구 지침을 가입 증표 설계에 참고): https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html

인증 성공과 가입을 연결하는 실제 보안 개선이다. 메일 인증을 처음부터 새로 구현했다는 성과로 부풀리지 않는다. SMTP 운영과 남용 방어·사용자 화면이 아직 없어 공개 배포 완료로 판정하지 않는다.
