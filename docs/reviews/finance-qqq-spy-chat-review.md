# QQQ·SPY 종목방 첫 대화 흐름

기준일: 2026-11-02. 시작 시 main `8dd842c`, 채팅 인증 초안 PR #6 `1f110ed`, 이메일 초안 PR #7 `cb528d3`를 확인했다. 기존 PR #6의 운동 모임 권한을 금융방에 재사용하지 않고 그 브랜치 위에 독립 기능 브랜치를 만들었다. 작업 트리는 비어 있었고 다른 저장소의 미커밋 변경은 건드리지 않았다.

## 목표와 구현

- `/api/v1/finance/rooms/{QQQ|SPY}/messages` GET은 익명에게 최근 30개를 오래된 순서로 준다. `afterId`는 해당 ID보다 큰 메시지 최대 30개를 오름차순으로 제공해 재접속 누락을 메운다. ID가 다른 종목인 경우에도 숫자 비교만 수행하므로 화면은 종목별 커서를 따로 보관해야 한다.
- POST는 JWT로 확인된 회원 ID만 작성자로 기록한다. 요청 본문은 UUID `requestId`와 내용만 허용하며 1천 자 이하·공백 제외 정책을 적용한다. 같은 회원·방·요청 ID의 반복은 기존 결과를 재사용하고 내용이 다르면 409를 반환한다. DB 고유키가 동시에 도착한 요청의 중복 저장을 막는다. 동시 충돌은 저장 단계에서 무결성 오류로 실패할 수 있어 추후 사용자 친화적 409와 재조회가 필요하다.
- 저장 및 트랜잭션 완료 뒤 `/topic/finance/rooms/{QQQ|SPY}`로 전송한다. 기존 STOMP 인증 인터셉터가 로그인 회원만 구독을 허용하고, 클라이언트의 broker 토픽 직접 전송은 거부한다. 익명은 REST 이력만 읽을 수 있다. 서버 종료나 브로커 장애 시 실시간 알림은 놓칠 수 있으므로 `afterId`로 복구한다.
- 고정 종목만 지원한다. 임의 종목방 개설·신고/삭제·전송 제한·웹 연결·운영 DB/SMTP 통합은 이번 완료 조건이 아니다. 특히 신고·삭제/제한이 검증되기 전 공개 커뮤니티 배포 완료로 표시하지 않는다.

## 시작·중간·완료 검증

시작: PR #6은 기존 채팅 STOMP 신원과 모임 참가 권한만 갖고 있었고, 금융 토픽과 공개 이력 API가 없었다. 중간: 별도 `financechat` 엔터티/저장소/서비스/컨트롤러, REST 읽기 보안, 토픽 구독 검사를 추가했다. 서비스 시험은 잘못된 종목·커서, 비회원 작성의 서버 경계, 재시도, 저장 실패, 롤백/커밋 후 방송을 확인한다. JPA 시험은 실제 H2에 저장한 고유키·종목별 커서를 확인한다. 원격 CI에서는 Java 21 전체 시험·bootJar 내용 및 실패/생략 건수를 검사한다.

로컬은 Java 17만 있고 Gradle 배포 파일 다운로드가 차단되어 전체 시험·실행 JAR를 로컬에서 수행할 수 없다. 원격 검사 결과는 PR 본문에 실제 실행 링크와 수를 기록한다. 실제 두 회원의 두 브라우저, 운영 DB, WebSocket 재연결, 화면 반영은 아직 확인하지 않았다. 시험 통과는 사업 수요나 금융 예측 성능을 입증하지 않는다.
