# WebSocket 채팅 신원과 대화방 권한 점검

## 변경 이유

이전에는 REST에서 JWT를 검증해도 WebSocket 요청 본문의 `memberId`가 작성자와 읽음 처리 대상이 됐다. 다른 회원의 ID를 넣어 메시지를 보내거나 `/topic/chat/rooms/{id}`에 직접 구독할 수 있었다. 채팅을 다른 서비스에 재사용하기 전에 STOMP CONNECT의 토큰을 검증하고, SEND와 SUBSCRIBE 때 서버가 확인한 회원 신원으로 방 접근을 확인한다.

## 구현 범위

- 연결 헤더에 Bearer 토큰이 없거나 유효하지 않으면 거절한다. 토큰이 확인되면 WebSocket 세션의 principal로 보관한다.
- `/app/chat/rooms/{id}`의 지정된 전송 명령과 `/topic/chat/rooms/{id}`·`/reads`의 구독만 허용하고, 매번 해당 모임 회원인지 확인한다. 클라이언트가 `/topic`에 직접 전송하는 것은 거절한다.
- 메시지·읽음·입장·퇴장에 쓰는 회원 ID는 인증된 세션에서 가져온다. 요청 본문에서 회원 ID를 받을 필요가 없다.
- 기본 허용 Origin은 로컬 개발 주소로 제한하고 실제 서비스 주소는 `app.websocket.allowed-origin-patterns`에서 설정한다.
- 기존 모임 회원 정책은 운동 모임용이므로 금융 종목 방으로 자동 재사용하지 않는다. 금융 종목 방의 공개 읽기·로그인 글쓰기 정책은 다음 별도 기능으로 구현한다.

## 검증 및 한계

CONNECT 인증 누락, 익명 구독, 허가되지 않은 구독·직접 전송, 허용된 방 접근 검사에 대한 단위 시험을 추가했다. 이 환경에 Java 21 컴파일러가 없어 로컬 Java 빌드 결과를 아직 주장하지 않는다. GitHub Actions의 Java 21 전체 시험 결과로 컴파일과 회귀를 확인한 뒤에만 기능을 완료로 표시한다. 운영 배포·브라우저 WebSocket 연결·금융 종목 방·실제 거래 데이터 인증은 아직 미검증이다.
