# EC2 공인 IP HTTPS 갱신 안전성 리뷰 (2026-11-12)

## 시작 근거

사용자 제공 공인 IP는 `18.191.135.212`. 원격 Java `main`은 초안 변경 이전이고 EC2의 기존 `docker ps`와 `docker volume ls` 출력은 비어 있다. AWS 콘솔 세션/SSM 명령 권한을 이 작업 공간에서 확인할 수 없으므로 실제 서버 변경이나 인증서 성공을 주장하지 않는다. 기존 `deploy/nginx.bluegreen.conf`의 80 서버는 모든 요청을 HTTPS로 보내 IP 인증서의 운영 중 webroot 갱신을 제공할 수 없었다.

## 중간 변경·오류

- 80의 인증 토큰 경로만 공유 디렉터리에서 제공하고 그 외는 HTTPS로 이동. Blue/Green 두 프록시에 읽기 전용 webroot를 연결하고 토큰 파일은 Git에서 제외.
- Certbot의 특정 IP 인증서에 연결할 루트 소유 배포 후크를 작성. 공인 IPv4/갱신 대상 일치, 인증서 SAN, 두 실행 중인 Nginx를 먼저 검사하고 대기→공개 프록시만 재생성/HTTPS 검증. 실패하면 인증서 갱신 성공이라고 기록하지 않으며 DB/Redis/Java에는 손대지 않음.
- 첫 버전에서는 후크를 저장소 경로에서 그대로 루트로 실행할 위험이 있어 루트 소유 `/usr/local/sbin` 복사 절차로 변경. 갱신 중 공개 Nginx 재생성으로 짧은 연결 단절 가능성은 남음.

## 완료 조건과 한계

변경 파일: Nginx/Compose/후크/단위 시험/격리 CI/운영 안내와 이 리뷰. 로컬 단위 시험 4개와 기존 전환 시험 4개·Python 컴파일·diff 검사 통과. 원격 Blue/Green CI의 HTTP 토큰 응답과 404, 전체 Java 시험·JAR·이미지 및 다른 게이트는 PR 커밋 기준으로 별도 확인한다.

사용자 결정 이후 공인 인증서의 실제 첫 발급, 자동 갱신 타이머, `renew --dry-run`, 외부 HTTPS, 실 SMTP 수신·회원가입, 두 브라우저 채팅, 구/신 버전 DB 호환과 전환/되돌리기는 미검증이다. IP 인증서는 약 6일 유효하고 EC2 자동 할당 공인 IP는 중지/시작 시 변경 가능하다. 이 기능은 **배포 준비**이며 운영 성공 판정이 아니다. 원본 가격·비밀값·비공개 모델 성과 수치는 포함하지 않는다.
