# EC2 읽기 전용 점검과 금요일 출시 준비

기준: 2026-11-11 한국 시간. 사용자는 오늘 배포와 11월 13일 금요일까지 연구 성과를 제외한 핵심 기능 완료를 지시했다. IAM 역할 설정과 EC2 터미널 접속 가능은 사용자 확인이며, 서버 상태의 실측과 구분한다.

## 시작

- 원격 main: Java `0b9e926`, 웹 `f64feb8`, Python `a993373`.
- Java 초안 #10→#11→#12→#13→#14가 쌓여 있고 #14 `b5b5cdd`의 원격 검사 6개가 성공했다. 아직 main의 Blue/Green 기능이 아니다.
- 웹 #3과 Python #8~#17은 별도 작업 중이다. 기존 로컬 미커밋 파일은 보존하고 Java #14 최신 커밋에서 새 작업 트리를 만들었다.
- 이 환경에는 AWS CLI·Docker·EC2 연결 도구가 없다. 사용자의 EC2 터미널과 이 개발 환경은 별개다. IAM 역할을 만들었다고 GitHub Secrets가 서버에 자동 복사되지 않는다.

## 구현과 중간 검증

- `deploy/ec2_preflight.py`: Python 표준 라이브러리만으로 Docker 접근·Compose·SSM 에이전트·IMDSv2 역할 연결·서버 env 파일의 존재와 권한·배포 소스 파일 존재를 점검한다.
- IMDSv2의 역할 목록만 조회한다. 역할 아래 임시 자격 증명은 요청하지 않는다. 역할이 보여도 권한 검증 완료로 표시하지 않는다. 메타데이터 접근 실패는 역할 없음이 아닌 미확인이다.
- env 파일 내용은 읽지 않고, 서브프로세스 양쪽 출력과 예외 세부값을 숨긴다. 컨테이너 기동/중지·파일 수정·DB 접근·SMTP 발송·Git 변경은 수행하지 않는다.
- 모든 점검이 양호해도 `deployment_status=NOT_VERIFIED`를 유지한다. 종료 코드 0은 진단 실행 완료이며 배포 허가가 아니다.
- 새 합성 시험 6개와 기존 전환·스키마 시험 10개, 합계 16개가 로컬에서 통과했다. 파일 권한/빈 파일/심볼릭 링크, 오류 출력 차단, 역할 목록 조회 범위, 배포 성공 오판 방지를 확인했다.

## 오류와 한계

- 웹 작업 트리 준비 명령의 상대 경로를 처음 잘못 지정했다. 파일 변경 없이 실패했고 작업 디렉터리를 수정해 재실행했다.
- Java 21은 있으나 로컬 Gradle 8.5 다운로드가 `Network is unreachable`로 실패했다. 전체 Java 시험·JAR·컨테이너 인수는 새 커밋의 원격 CI로 확인해야 하며 이전 커밋 통과로 대체하지 않는다.
- 실제 EC2에서 이 점검은 아직 실행되지 않았다. IAM 세부 정책·SSM 원격 명령 권한·Parameter Store/KMS 권한·실제 TLS/SMTP/DB 상태를 검사한 도구가 아니다.
- 외부에서 MySQL/Redis/Java 포트가 차단됐는지, 유효한 TLS와 실제 두 브라우저 채팅, 백업 복구, 기존 WebSocket 연결 유지 역시 별도 인수 대상이다.

## 오늘 실행 순서

1. EC2 저장소를 바꾸지 않고 점검 스크립트만 검토/실행해 안전한 JSON 결과를 확인한다.
2. API 도메인/TLS, 서버 비밀 설정 경로, SMTP 시험 수신처, 기존 MySQL 데이터 존재와 백업을 확인한다. 비밀값은 채팅으로 받지 않는다.
3. Java #10~#14의 구체적 변경과 CI를 검토해 사용자가 병합할 대상을 확정한다. 초안을 자동 병합하지 않으며 승인 main 커밋을 고정한다.
4. 승인된 이미지로 앱을 기동하고 DB/Redis health, HTTPS API, 실제 가입/로그인과 QQQ/SPY 대화를 확인한다. 첫 빈 설치와 기존 서비스 업데이트를 구분한다.
5. 두 버전은 같은 MySQL/Redis를 사용한다. 대기 버전 검증→트래픽 전환→사후 검증 순서로 진행하고 실패 시 이전 버전으로 복귀한다. MySQL 볼륨 삭제 금지. Mailpit/자체 서명 시험 구성을 운영에 쓰지 않는다.
