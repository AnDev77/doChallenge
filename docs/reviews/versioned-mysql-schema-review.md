# Blue/Green 이전 버전 관리 MySQL 스키마

기준일: 2026-11-09. doChallenge `main` `0b9e926`와 초안 PR #10·#11을 확인하고 #11 위의 별도 후속 브랜치에서 시작했다. PR #10은 격리 Docker의 가입·채팅 저장/재기동 시험, PR #11은 `ddl-auto: update`와 마이그레이션 부재를 차단하는 게이트다. 두 PR의 기존 변경과 미커밋 작업 트리를 덮어쓰지 않았다.

## 시작·중간 근거와 작업량

- 시작: 운영 JPA가 스키마를 자동 변경하고 버전 관리 SQL이 없어 Blue/Green의 공유 DB 계약을 검증할 수 없었다.
- 중간: 빈 MySQL 8.4용 V1 테이블 7개와 인덱스·고유 제약, Flyway MySQL 의존성, 운영 `ddl-auto: validate`와 자동 baseline 금지를 추가했다. 기본 프로필은 기존 H2 단위 시험을 위해 Flyway 비활성이고 운영 프로필만 활성이다.
- 소스 게이트는 자동 baseline, 빠진 테이블, 파괴적 초기 SQL을 차단한다. Docker 스모크는 Flyway 이력 `1`, 가입·채팅, 컨테이너 재생성 뒤 이력·데이터 유지를 확인한다. 변경량은 빌드·운영 설정 3개, SQL 1개, 게이트/시험 2개, Docker 스모크 1개, 배포 안내와 리뷰다.

## 완료 판정과 한계

로컬 Python 게이트 시험 6개·구문·diff 검사에 성공하고 저장소의 `SCHEMA_SOURCE_READY`를 확인했다. Java 21은 설치돼 있으나 Gradle 배포 파일 다운로드가 이 환경의 네트워크에서 차단돼 로컬 전체 시험과 실행 JAR 빌드는 시작하지 못했다. 원격 Docker 인수와 PR 게이트 결과는 실행 뒤 기록한다. 이 변경은 **새 빈 DB의 구조를 통제하는 기능**이다. 기존 운영 DB는 자동 baseline 없이 기동을 거부하며, 백업·실제 DDL 비교·복제 DB의 baseline 검증이 별도로 필요하다. 두 버전의 동시 기동·Nginx 트래픽 전환·되돌리기와 WebSocket 드레인도 아직 구현되지 않았다. 따라서 EC2 운영 Blue/Green과 실제 회원 서비스 배포는 HOLD다. 합성 Docker 가입·채팅 시험은 실 SMTP 수신과 운영 사용자 수요를 입증하지 않는다. 금융 예측의 독립 미래 성능도 HOLD다.
