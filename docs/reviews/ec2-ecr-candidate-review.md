# ECR 이미지로 EC2 내부 후보 검증

- **시작:** 원격 main `553d113`을 기준으로 기존 #19 읽기 전용 경로, #20 외부 API 검증, #17 Blue/Green/TLS와 중복되는지 확인했다. 사용자는 단일 EC2/Nginx 배포 자동화를 선택했다.
- **중간:** 시험한 컨테이너 이미지를 같은 실행의 산출물로 전달해 별도 권한 작업에서 ECR에 올린다. SSM에는 digest만 넘기며 문서와 인스턴스를 지정한다. 후보는 독립 DB·네트워크·루트 소유 설정을 쓰고 운영 SMTP·공개 포트에 의존하지 않는다. 합성 SMTP를 끈 상태에서 기본 메일 health가 전체 상태를 내리지 않도록 후보에만 메일 지표를 껐다.
- **완료 기준:** PR에서 합성 SSM 시험과 권한 범위, Java 전체 시험·실행 JAR, 후보의 실제 Docker/MySQL/Redis 통합, 두 종목의 조회와 익명 쓰기 거부, 포트 미공개를 확인한다. AWS 자격을 받는 단계는 PR에서 생략된다. 로컬에는 Docker가 없고 Gradle 8.5 다운로드가 차단됐다. Java와 컨테이너 시험은 원격 결과로 판정한다. SSM 템플릿 치환 구문과 혼동되지 않게 이미지 검사에는 Docker 출력 템플릿을 사용하지 않는다.
- **작업량:** GitHub 워크플로, 독립 Compose와 기동/스모크 코드, SSM·CloudFormation 생성기와 호출기, 합성 시험, 초기 설정·리뷰 문서. 기존 운영 역할·이미지·데이터는 변경하지 않았다.
- **남은 검증:** 실제 AWS 리소스 생성, ECR 게시와 EC2 수신, 외부 HTTPS, 실 SMTP, 기존 데이터 동시 호환, Blue/Green 전환과 복귀는 미실행이다. 운영 서비스 배포나 예측 검증으로 계산하지 않는다.
