# Java 브리핑 생성: 근거 선택 → Spring AI → 초안 저장

기준일: 2026-11-18. 대상: `feat/java-briefing-generation`. 이 단계는 **내부 서비스의 동기 초안 생성**이다. 호출하는 작업 실행기·관리 API·Kafka 소비자·공개 GET 연결은 없다. 기본 설정은 모델을 비활성화한다.

## 호출 순서

1. 미래의 작업 실행기가 `BriefingGenerationService.generate(symbol, query, asOf)`를 호출한다. `asOf`는 DB `DATETIME(6)`에 맞춰 마이크로초로 잘라 검색·저장에 함께 쓴다.
2. `EvidenceRetriever.search(symbol, query, asOf, 7, 8)`가 해당 시점에 수집·검증된 최신 원문 버전의 청크를 최대 8개 고른다. 0개면 모델을 호출하지 않고 실패한다. 영문 공시·한국어 질의의 표현 차이와 LIKE 전수 검사 비용은 이전 검색 기준선의 한계다.
3. 모델 입력은 종목·질의·시각과 각 근거의 청크/문서 ID, SEC accession, URL, 원문/청크 해시, SEC 접수·수집 시각, 청크 본문을 JSON으로 만든 것이다. 본문과 질의는 외부 자료이므로 **사용자 메시지의 데이터**로 보내고, 시스템 메시지는 그 안의 명령을 무시하고 제공된 근거만 요약하도록 요청한다. 프롬프트만으로 지시문 주입을 완전히 방어했다고 주장하지 않는다.
4. `SpringAiBriefingModel`은 `ChatModel`이 설정된 경우 Spring AI `Prompt(SystemMessage, UserMessage)`로 한 번 호출한다. 응답은 최대 8,192자 JSON이어야 하며 정확히 `summary`(한국어 요약 문자열), `citation_ids`(제공된 청크 ID 정수 배열) 두 필드만 허용한다. 중복 키·추가 필드·뒤따르는 텍스트·존재하지 않거나 중복된 ID·인용 없음·4,000자 초과 또는 숫자가 든 요약은 거부한다. 숫자 금지는 수치 사실 대조가 없는 현재 단계의 임시 정책이다. **인용 ID 검사만으로 문장과 원문 내용이 의미상 일치하는지 알 수 없다.**
5. 통과하면 기존 `BriefingDraftService.create`가 같은 `symbol/query/asOf`로 다시 검색한다. 모델 호출 중 새 원문이 해당 기준 시각의 최신 버전이 되면 구버전 인용이 거부되고 초안이 저장되지 않는다. 모델 호출을 DB 트랜잭션에 묶지 않는다. 초안과 인용 행의 저장만 별도 트랜잭션이다. 실패해도 모델 호출 비용은 되돌릴 수 없다. 성공 결과도 `DRAFT`이며 사람의 검토 전에는 공개 조회에서 보이지 않는다.

## 모델 연결과 비용 경계

`build.gradle`에 Spring AI 1.1.8 BOM의 OpenAI 모델 스타터를 추가했다. 기본 `BRIEFING_CHAT_PROVIDER=none`, 임베딩 `none`이라 앱 기동·사용자 GET이 유료 호출을 하지 않는다. 운영자가 별도 작업 환경에 `BRIEFING_CHAT_PROVIDER=openai`, `OPENAI_API_KEY`, `BRIEFING_CHAT_MODEL`을 설정해야 ChatModel이 생성된다. 모델 기본 식별자는 `gpt-5-mini`, 최대 생성 토큰 설정값은 `1024`로 두되 실제 모델·비용 상한과 계정 설정을 승인받은 환경에서 시험해야 한다. 키는 문서·Git·로그에 넣지 않는다. 이 서비스는 아직 호출 엔드포인트가 없어 환경 변수만 설정해도 생성 작업은 시작되지 않는다.

모델 응답 크기, 입력 최대 청크 8개·청크당 1,500자, 검색어 256자 제한은 예상 호출량의 상한을 낮춘다. 실제 과금·토큰 사용량·모델 지연은 호출을 실행하고 계정 사용량을 확인하기 전까지 알 수 없다. 프로바이더 타임아웃/재시도 정책도 실제 모델 연결 인수 전에 검증해야 한다.

## 시험·다음 인수

H2 MySQL 모드 V3→V4의 실제 원문/청크·READY 상태에서 모의 모델 출력을 사용해 `DRAFT` 저장과 미승인 비공개를 확인한다. 0건 근거는 모델 호출 0회, 잘못된 JSON·숫자·가짜 인용·중복 키/ID는 저장 0건, 모델 호출 중 새 `PENDING` 원문이 들어오면 재검색에서 실패하는 사례를 검증한다. 별도 어댑터 시험은 시스템/사용자 메시지 분리와 모델 미설정 실패를 확인한다.

이 시험은 실제 SEC → MySQL 수집, 실제 OpenAI 호출, 한글 품질/문장 의미 대조, 30건 검색 평가, 수치 대조, 검토 권한·화면, 공개 API 전환, Kafka, 운영 배포의 완료 증거가 아니다. 실제 자료·모델 키·예산을 확인한 제한 호출과 고정 근거 평가가 다음 인수이며, 그 뒤에 인증된 검토·공개 전환을 진행한다.
